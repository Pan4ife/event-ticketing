## Goal
The database has a `users` table created by a Flyway migration, and the backend has a `User` JPA entity and a
Spring Data repository that match it (Hibernate `ddl-auto=validate` accepts them).

## Context
- PRD: `docs/PRD.md` → "Scope" (roles Guest, User, Admin).
- Details: `docs/reference/technical-spec.md` → "7. Database Design" → "User" (fields and constraints).
- Code: `backend/src/main/resources/application.properties` (`ddl-auto=validate`, Flyway owns the schema);
  `backend/src/main/resources/db/migration/` is empty — this is migration `V1`.
- Contract the tests rely on (they use plain SQL through `JdbcTemplate`, so they compile before the entity exists):
  - table `users`, columns `id`, `email`, `password_hash`, `first_name`, `last_name`, `role`, `status`,
    `preferred_language`, `created_at`, `updated_at`;
  - `id` is generated by the database (type is Slava's choice; `bigint` identity is the simple default);
  - `email` unique; `email`, `password_hash`, `first_name`, `last_name`, `role`, `status`, `created_at`,
    `updated_at` are `NOT NULL`; `preferred_language` may be null for now (filled by the profile feature);
  - `role` holds the text `USER` or `ADMIN`, `status` holds `ACTIVE` or `BLOCKED`.

## Allowed / not allowed (on top of AGENTS.md)
- Allowed to change: `backend/src/main/resources/db/migration/V1__*.sql`, new files in
  `backend/src/main/java/io/github/pan4ife/eventticketing/` (entity, repository), `backend/src/test/**`.
- Not allowed: other tables (categories, events, bookings come with their features); endpoints; `pom.xml`.
- Agents explain, write tests in `backend/src/test/`, review. They do not edit `backend/src/main/`.

## Acceptance criteria
1. [auto] `./mvnw verify` is green; the application context starts, so Hibernate validated the entity against the schema.
2. [auto] Test `UsersTableTest` (written first by the tester): a full row can be inserted; a second row with the same
   `email` fails; a row without `password_hash` fails; a row without `role` fails.
3. [judge] `User` is a JPA entity in a `domain` package, mapped to every column above; `role` and `status` are Java
   enums stored as text (`@Enumerated(EnumType.STRING)` or equivalent).
4. [judge] `UserRepository` is a Spring Data interface in a `repository` package; nothing else is added.
5. [judge] Changed files: one migration `V1__*.sql`, the entity, the two enums, the repository, the test.
